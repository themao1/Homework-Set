## 二、原代码中的「可改进」批注 → 处理结果

| 原批注 | 处理 |
|---|---|
| `bank_map_app.py` 越过 SQLOperation 直接操作数据库 | 前端不再 `import sqlite3`，全部走 DAL |
| `load_banks` 没有像 DAL 那样转义输入 | 统一 `_escape_like` + `ESCAPE`，参数一律 `?` 占位 |
| `d_lng` 在大范围下会「爆炸」 | 粗筛下推到 SQL 的经纬度矩形（`BETWEEN`），再按 Haversine 精算 |
| `pd.isna` 挡不住空字符串 | 展示层统一 `fmt_value`（`None`/空串/`[]` 都当缺失） |
| 外部数据拼 HTML 未实际转义 | 统一 `html.escape`，防 XSS |
| 数据量大要考虑 `st.cache_data` 缓存 | 类型/城市候选值加 2 分钟缓存 |
| `upsert_banks` 空 rows 仍开连接计数 | 空列表直接返回 `(0, 0)` |
| 线性退避、未区分永久错误 | 指数退避 + `FATAL_INFOCODES` 永久错误不重试 |
| 没有处理 JSON 解析失败 | 捕获 `ValueError`（含 JSON 解码错误）并可重试 |
| `--target` 只抓银行、参数写死 | `config.LAYERS` + 命令行参数（城市/关键词/类型/页数） |
| 迁移/建表重复代码、索引无参数化 | 建表与索引由「图层表名」推导，迁移按 v1/v2/v3 分情况 |
| `status` 未设 `row_factory` | 统一 `sqlite3.Row`，按列名取值 |
| `clean_row` 认为 `lng=0/lat=0` 合法 | 保留该判断，另加经纬度**合法范围**校验 |
| 抓取边抓边写可以省内存 | 当前仍是分批入内存后入库，注释标明了改造点 |

## 三、地图不加载的三个坑（重点）

这三个问题都能表现成「地图出不来」，而且会互相掩盖，最后是靠**无头 Chrome + DevTools 协议**
直接读页面状态才定位清楚的。

### 坑 1：folium 默认从公网 CDN 取资源

folium 生成的 HTML 头部挂 10 个 CDN 资源，其中 `leaflet.js` 或
`leaflet.awesome-markers.js` 拉不到时，地图直接白屏或标记点报错。

本机实测 `code.jquery.com`、`cdn.jsdelivr.net`、`data.streamlit.io` 均不可达，而高德瓦片可以。

**处理**：`map_assets.py` 把 Leaflet 指向本地 `libs/`；静态导出用相对路径
（`libs/leaflet.js`），Streamlit 组件 iframe 用 `data:` URL 内嵌；其余 8 个 CDN 依赖删除。

### 坑 2：`folium.Popup` 内部依赖 jQuery

folium 的 Popup 模板用 jQuery 把 HTML 转成 DOM 节点：

```js
var html_xxx = $(`<div ...>...</div>`)[0];   // 需要 jQuery
```

删掉 jQuery 后，第一个标记执行到这行就抛 `ReferenceError: $ is not defined`，
**整段地图脚本中断**：227 个点只画出 1 个，重渲染还会报 `Map container is already initialized`。

**处理**：标记点改用 Leaflet 原生 **tooltip**（模板字符串，零依赖），悬停显示
名称/地址/电话/类型；点击标记由下方详情卡片展示完整信息。

### 坑 3：`st_folium` 回传值的类型与字段

- `center` 回传的是 `{"lat": .., "lng": ..}` 字典，直接 `list(center)` 得到 `['lat','lng']`，
  喂给 `folium.Map` 会抛 `ValueError`，于是**任何一次地图交互后的重跑都会把整块地图变成报错框**；
  → 新增 `as_center()` 归一化成 `[lat, lng]`，写进 `session_state` 前就转换。
- 标记 id 编码在 tooltip 里，但正确回传字段是 `last_object_clicked_tooltip`
  （不是 `last_object_clicked["tooltip"]`），`returned_objects` 里必须显式声明；
  → 补上该字段，解析改用 `search(r"#(\d+)")`（tooltip 会被包一层容器）。

## 四、验证方法

静态地图与前端都用无头 Chrome 验证，不靠「看起来应该没问题」：

```bash
# 1) 静态地图：数 DOM 里真实渲染出来的标记点，并截图
chrome --headless=new --virtual-time-budget=8000 --dump-dom file:///.../banks_map.html
chrome --headless=new --virtual-time-budget=8000 --screenshot=map.png file:///.../banks_map.html

# 2) 前端：用 CDP（Chrome DevTools 协议）连上页面，读组件 iframe 内部状态
#    leaflet 版本 / 标记点数量 / 是否有 JS 异常 / 点击标记后详情是否出现
#    （探测脚本是一次性的，没有入库；用 chrome --remote-debugging-port=9222 可自行接）
```

关键结论：

```
静态 HTML：227 个标记全部渲染，页面内 "$(" 出现 0 次
前端 iframe：Leaflet 1.9.4、227 个标记、无 JS 异常、jQuery undefined
可信鼠标点击标记 → 详情卡片出现「🏦 招商银行(深圳坂雪岗支行)（id=9）」
点击地图空白 → 「📍 点击位置周边 1000 米内的银行网点」
```

## 五、数据结构迁移

- v1：`banks` 七列（id/name/address/lng/lat/tel/type）
- v2：+ `source` / `created_at` / `updated_at`
- v3：+ `city` / `district` / `adcode` / `extra`，新增 `communities` 与 `feed_back`

迁移由 `ensure_schema` 自动完成，幂等：空库建全套、v1 整表重建（保留原 id）、v2 补列建表。
升级前建议先备份 `banks.db`。

## 六、发布前整理（准备上传 GitHub）

- **仓库卫生**：`.env` 从未进入历史（已核查），仓库里只有 `.env.example`；
  取消对 `.idea/` 的跟踪；`.gitattributes` 统一 LF，避免 Windows/macOS 来回改行。
- **README 拆分**：README 只放访客需要的内容（功能、快速开始、表结构、配置项），
  改造细节与踩坑放进本文。
- **可移植性修复**：命令行输出原本带 emoji，在 Windows 默认的 GBK 控制台下
  `print` 会抛 `UnicodeEncodeError`，别人 clone 下来跑第一条命令就崩。
  现在 CLI 文案全部改为纯文本（emoji 只保留在网页界面），并在各命令行入口调用
  `config.make_stdout_safe()`，把编码错误降级为 `?` 而不是中断。
- **新环境验证**：`git clone` 到干净目录，用未设置 `PYTHONIOENCODING` 的终端跑
  `db status` / `review list` / `export-map`，确认开箱可用。

## 七、已知限制


- 单机 SQLite，未做多用户并发写入优化
- 审核是命令行工具，没有账号体系与网页后台
- 高德文本检索单关键词最多 100 页，城市数据量大时要按区县拆分检索
- 地图不做点位聚合，大数据量时建议走列表分页
- 底图瓦片依赖高德服务器，完全离线时只有标记点与控件
